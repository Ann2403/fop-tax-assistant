# Eval-набір

Перший eval-набір проєкту: 10 запитів з очікуваними відповідями. Кожен рядок `questions.jsonl` — один кейс.

## Формат кейсу

| Поле | Тип | Опис |
|---|---|---|
| `id` | string | Унікальний ідентифікатор, `q01`…`q10` |
| `type` | string | `rag` — питання про правила; `calc` — розрахунок/строки; `agent` — багатокрокова задача; `guardrail` — відмова або ескалація |
| `query` | string | Запит користувача дослівно |
| `context` | object | Вхідні дані: група ФОП, дата запиту, фікстури (`statement`, `nbu_rates`) |
| `expected_answer` | string | Еталонна відповідь людською мовою |
| `expected_values` | object | Числа/дати, які перевіряються точно (код, не LLM-суддя) |
| `must_include` | string[] | Факти, які обов'язково мають бути у відповіді |
| `must_not_include` | string[] | Те, чого у відповіді бути не повинно |
| `expected_tools` | string[] | Інструменти, які агент має викликати |
| `expected_behavior` | string | `answer` / `answer_with_warning` / `ask_human` / `refuse` |
| `sources` | string[] | Стаття ПКУ або закону, що обґрунтовує відповідь |
| `verified` | bool | `true`, коли відповідь звірено з ЗІР/ПКУ вручну |

## Як оцінювати

- `expected_values` — точне порівняння (суми до копійки, дати).
- `must_include` / `must_not_include` — перевірка рядків або LLM-суддя.
- `sources` — цитата у відповіді має збігатися зі статтею й бути в знайденому фрагменті.
- `expected_tools` — з трасування агента.
- `expected_behavior` — для `ask_human` і `refuse` фінальна декларація не має бути сформована.

## Фікстури

- `fixtures/statement_q3_2026_case08.csv` — виписка для q08 (валюта, власні кошти, повернення, комісія банку).
- `fixtures/statement_q3_2026_case09.csv` — виписка для q09 (неоднозначне «повернення позики»).
- `fixtures/nbu_rates.json` — зафіксовані курси НБУ, щоб тест не залежав від живого API.

Суми у виписках: додатні — надходження, від'ємні — списання.
