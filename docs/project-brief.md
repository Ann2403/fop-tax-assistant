# Податковий помічник ФОП 3 групи — бриф проєкту

> ДЗ до заняття 2: задача, розбивка на підзадачі, критерій успіху, перший eval-набір.
> Eval-набір: [`eval/questions.jsonl`](../eval/questions.jsonl), опис формату: [`eval/README.md`](../eval/README.md).

## 1. Задача

AI-асистент для ФОП і бухгалтерів малого бізнесу, який:

1. **Відповідає на податкові питання** з посиланням на конкретну статтю Податкового кодексу (ПКУ) або роз'яснення ДПС (ЗІР).
2. **Готує чернетку квартальної декларації** ФОП 3 групи (неплатник ПДВ) з банківської виписки.

**Проблема.** Правила розкидані по сотнях сторінок ПКУ і тисячах роз'яснень, часто змінюються. Помилка в класифікації доходу чи строку — донарахування і штраф. Ручна підготовка декларації займає 1–3 години на квартал.

**Межі (scope).**

- ✅ ФОП 3 група без ПДВ, одна форма декларації, чернетка для перевірки людиною.
- ❌ 1/2/4 групи (для декларацій), ПДВ, наймані працівники, подання в Електронний кабінет (потребує КЕП — завжди робить людина).

## 2. Підзадачі

### Шари системи

| Шар | Що робить | Блок курсу |
|---|---|---|
| Інтерфейс | Чат + завантаження виписки (CSV/PDF) | 4 |
| Роутер намірів | Питання про правила / розрахунок / декларація / поза межами | 1 |
| Витяг даних | PDF-виписка → JSON транзакцій за строгою схемою; порівняння платної й локальної моделі | 1 |
| RAG | Пошук по ПКУ + ЗІР, відповідь з цитатою; перевірка, що цитата є у знайденому фрагменті | 2 |
| Агент | Багатокрокова задача «підготуй декларацію» через інструменти | 3 |
| Детермінований розрахунок | Гроші, ставки, ліміти рахує код, не LLM | 3 |
| Продакшн | API, автентифікація, журнал рішень агента, облік токенів і вартості, моніторинг | 4 |

### Дані

| Джерело | Навіщо |
|---|---|
| ПКУ (zakon.rada.gov.ua) з датою редакції | Основна база RAG |
| ЗІР ДПС (zir.tax.gov.ua) — питання й відповіді | RAG + розширення eval-набору |
| Індивідуальні податкові консультації ДПС | Складні реальні кейси |
| Синтетичні виписки з відомою правильною відповіддю | Точний eval декларації |
| Конфіг ставок і лімітів з датами дії | Ставки не зашиті в код |

Реальні виписки в репозиторій не потрапляють.

### Інструменти (tools)

| Інструмент | Що робить |
|---|---|
| `parse_statement(file)` | Виписка → транзакції |
| `classify_transaction(tx)` | LLM: дохід / повернення / власні кошти / продаж валюти / не дохід / сумнівна |
| `nbu_rate(currency, date)` | Офіційний курс НБУ |
| `calc_tax(income, period)` | ЄП 5%, ВЗ 1%, ЄСВ |
| `check_limit(income_ytd, year)` | Ліміт доходу групи |
| `tax_calendar(period)` | Строки подання й сплати |
| `search_law(query)` | RAG по ПКУ та ЗІР |
| `fill_declaration(data)` | Чернетка декларації (JSON + PDF) |

У Блоці 3 інструменти оформлюються як MCP-сервер.

### Що може піти не так

| Ризик | Захист |
|---|---|
| Вигадана стаття | Цитата приймається, лише якщо її текст є у знайденому фрагменті; інакше «не знайшов джерела» |
| Застаріла норма | Версіонування документів за датою редакції; ставки в конфігу з датою дії |
| Хибна класифікація транзакції | Сумнівні транзакції — на рішення людині |
| Арифметика LLM | Усі суми рахує код |
| Помилки OCR у PDF | Звірка суми транзакцій з оборотами виписки |
| Слабка українська в локальній моделі | Порівняння метрик у Блоці 1 |
| Prompt injection у призначенні платежу | Текст транзакцій — дані, не інструкції |
| Чернетку подають як готову | Статус «чернетка» + обов'язкове підтвердження людиною |
| Персональні дані | Маскування в логах, реальні виписки поза git |

## 3. Критерій успіху

| Метрика | Ціль |
|---|---|
| Правильність відповідей на питання | ≥ 80% |
| Відповіді з перевірюваним джерелом | 100% |
| Вигадані статті | 0 |
| ЄП і ВЗ на синтетичних виписках | точно до копійки у ≥ 95% |
| Сумнівні транзакції, передані людині | ≥ 90% |
| Запити поза межами — відмова або ескалація | 100% |
| Час відповіді на питання | < 15 с |
| Вартість: питання / декларація | < $0.05 / < $0.30 |

**Одним реченням:** ФОП отримує правильну чернетку декларації і відповіді з джерелами, а кожне сумнівне рішення система явно показує людині.
